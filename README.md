# Рабочая обвязка (`infra/`)

Всё, что **следит** за проектами и обслуживает хост: юниты и таймеры systemd, сторожа, дампы баз с учением
восстановления, проверка дрейфа, сканер секретов, ребут-чек, реестр проектов, контракт нового проекта и
его шаблон, операции над стеком вендора платформы. Прикладного кода здесь нет — только обвязка.

**Почему отдельная папка, а не `ops/` в каждом проекте.** Обвязка обслуживает ВСЕ проекты. Копия по
проектам разъехалась бы молча: у одного сторожа оказался бы свой набор повторов, у другого — своя форма
«что считать живым», и оба молчали бы.

**Runbook хоста** — отдельный документ конкретного развёртывания (ресурсы машины, что где лежит, окно
рестарта, что нельзя держать два моста). Он описывает хост, а не обвязку, и в этот репозиторий не входит.

## Что внутри

| Папка / файл | Что это |
|---|---|
| `systemd/` | 21 юнит и 15 таймеров + `install.sh` (рендер, раскладка, включение) + `README.md` |
| `health/` | 10 сторожей (`health.sh` — мост и приём наблюдаемости, `health-*.sh` — службы проектов, `health-drift.sh` — дрейф конфигурации, `health-prompts.sh` — тексты агентов против выкаченных ревизий) |
| `lib/` | `workspace.sh` (одно место «где воркспейс»), `service_guard.sh` (контейнер или юнит, пропуск по оси вендора), `vendor.sh` (таблица вендоров и их возможностей), `db-targets.sh`, `dsn.sh`, `alert.sh` |
| `alert-send.py` + `lib/alert.sh` | Доставка алерта владельцу: **один вход** (`alert_send`) вместо копий в каждом стороже. Порядок путей: мост → MTProto без моста (только при свободной сессии, правило «одна сессия — один процесс») → маркер+журнал. Проверка доставки: `bash lib/alert.sh --probe` |
| `vendors.tsv` | ТАБЛИЦА вендоров платформы: возможности вендора и имя проекта его стека (см. ниже) |
| `vendor-stack.sh` + `vendor-compose/<вендор>.yml` | стек вендора: наш оверлей запуска (порты, лимиты, `restart: unless-stopped`) и единственный владелец операции `up\|down\|status`. Вендор — параметр (`PLATFORM_VENDOR` или `VENDOR=…`), цели — `make stack-up/stack-down/stack-status` |
| `lib/vendor-probes/<вендор>.sh` | проба оси наблюдаемости у вендора; обязательство одинаково: функция `vendor_probe_telemetry` есть у каждого вендора из `vendors.tsv`, нет файла — названный отказ |
| `db/` | `db-dump.sh` + `db-restore-drill.sh` (дамп не бэкап, пока его не восстановили), `db-inventory.py`, `schema-gate.sh` (**ручной** гейт схемы ЖИВОЙ базы по компонентам её владельца). Цели дампа — `lib/db-targets.sh`: `realty` и `news` в нашем стеке данных (`data`), `vectors`/`reminders` — в `realty`; сервер каждой базы учение называет и в стек платформы не пускает |
| `checks/` | `check-stack-drift.py` (движок сторожа дрейфа), `reboot-roundtrip.sh`, `scan-secrets.sh`, `gpu-verdict.py`, `debt-window.sh`, `backup-sessions.sh`, `list-our-files.sh`, `foreign-source-probe.sh` |
| `logs/` | `bridge-log-trim.sh` — обрезка файла лога для ХОСТОВОГО пути (в контейнерах логи крутит docker) |
| `status.sh` | **ручной** снимок: контейнеры и ошибки в логе |
| `compose-projects.tsv` | РЕЕСТР проектов воркспейса: `имя проекта ⇥ файл композа`. Один на всех — по нему сторож, дрейф, ребут-чек и гейты находят службы |
| `templates/project/` | Шаблон нового проекта; `new-project.sh` разворачивает его и добавляет строку в реестр |
| `templates/workspace/.env.example` | Образец ОБЩЕЙ ОСНОВЫ (`$WORKSPACE/.env`): ключи, которые обвязка читает из неё, и перечень того, что сюда не кладётся |
| `CONTRACT.md` | **Контракт**: что обязан сделать новый проект, и чем это проверяется |
| `Makefile` | `install`, `check`, `health`, `status`, `schema`, `dump`, `restore-drill`, `secrets`, `drift`, `reboot-*`, `stack-*` |

**Ручные инструменты** (`status.sh`, `db/schema-gate.sh`) намеренно НЕ вызываются ни гейтом, ни
таймером: они для человека. Так и написано, чтобы следующая смена не искала несуществующий автозапуск.

## Как поставить

Общая основа окружения (`$WORKSPACE/.env`) собирается по образцу `templates/workspace/.env.example`:
без этого файла ни один сторож, дамп или проверка не работают.

```bash
bash infra/systemd/install.sh          # проверить пути, разложить юниты, daemon-reload, enable --now
make -C infra check                    # офлайн-проверка: пути в юнитах сходятся с фактом
make -C infra health                   # прогнать сторожей
```

## Два корня, и почему это настройка

Обвязка знает два корня: **свой** (`infra/`) и **корень воркспейса** (там `.env`, каталоги проектов и
сценарии). Корень воркспейса берётся из `AGENT_WORKSPACE` (её задают юниты через `Environment=`), а при её
отсутствии — выводом от файла. Правило проекта: **путь к данным — настройкой, а не от расположения кода.** Иначе
перенос модуля уводит путь внутрь `site-packages`, и процесс молча не подключается — при зелёных тестах и
`healthy` контейнерах. Поэтому `infra/` можно вынести в свой репозиторий: правится настройка, а не скрипты.

## Вендоры платформы

Вендоров два, и они **равноправны**: любой выбирается осью `PLATFORM_VENDOR` (или `VENDOR=…` в вызове).
Различаются они не старшинством, а набором возможностей, и набор записан ДАННЫМИ в `infra/vendors.tsv`:

| вендор | `runtime` | `channel` | `http_api` | `telemetry_receiver` | `span_form` | проект стека |
|---|---|---|---|---|---|---|
| `agenta` | да | да | да | да | да | `agenta-oss-gh` |
| `openlit` | нет | нет | нет | да | да | `openlit` |

* `runtime` — умеет исполнять роли агентов;
* `channel` — имеет канальный путь (сообщения и журнал сессий);
* `http_api` — имеет HTTP API здоровья платформы;
* `telemetry_receiver` — принимает OTLP-трассы;
* `span_form` — есть адаптер формы спана в общем слое;
* `compose_project` — имя проекта compose его стека (пусто — стек поднимается не нами).

Код спрашивает ВОЗМОЖНОСТЬ, а не имя: сторож пропускает службу по `runtime=no` (`guard_skip_if_other_vendor`),
сверка промптов — по `http_api=no`, проба наблюдаемости берётся файлом `lib/vendor-probes/<вендор>.sh`.
Новый вендор добавляется строкой в `vendors.tsv` и файлом пробы — правок в скриптах это не требует.

Вендор, чей стек поднимаем мы, получает оверлей `vendor-compose/<вендор>.yml`; для остальных операция
неприменима, и `vendor-stack.sh` называет причину, а не молчит.

## Стек вендора: что делает `vendor-stack.sh`

`bash infra/vendor-stack.sh up` (вендор — из `PLATFORM_VENDOR`): префлайт (клона вендора и оверлея нет →
названный отказ; порты свободны; свободной памяти не меньше порога) → закреплённый образ → подъём →
готовность → замер. Приём OTLP — порт `4318` (охраняется `firewall/docker-ports-guard.sh`), UI —
`127.0.0.1:3300`. Скрипт НЕ трогает `PLATFORM_VENDOR` и не гасит стек другого вендора: выбор оси —
осознанное действие владельца.

## Как добавить проект

Смотри `CONTRACT.md` — восемь правил и чек-лист. Быстрый путь: `bash infra/new-project.sh <имя> <порт>`.
