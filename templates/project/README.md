# Проект `__PROJECT__`

Один абзац: что это и КОМУ нужно (`кто живой потребитель`). Общий слой — только из `agent_core`;
пакет проекта — `__PROJECT___agent` (создаётся `new-project.sh` из этого шаблона).

* поднять: `bash __PROJECT__-up.sh` (и `status`, `stop` — см. скрипт)
* композ: `compose.__PROJECT__.yaml`, имя проекта `__PROJECT__`, порт хоста `__PORT__` (loopback)
* том: `__PROJECT__-data` (объявлен ЯВНЫМ именем, см. правило 7 контракта)

## Обязанности по контракту

Полный список — `infra/CONTRACT.md`; коротко для этого проекта:

1. Своя папка и композ со своим `name:`, сеть вендорская (`external: true`).
2. Свой пакет `__PROJECT___agent`; чужой проект не импортировать.
3. Адреса и `SESSIONS_DIR` задаются явно (лончер и композ).
4. Пути к данным — настройкой, не от `__file__`.
5. Лончер + `Makefile` + этот README; порты только на `127.0.0.1`; `restart: unless-stopped` и `mem_limit`.
6. Строка в `infra/compose-projects.tsv` (её добавляет `infra/new-project.sh`).
7. Тома — с ЯВНЫМ `name:`; имя тома по РОЛИ (`<роль>-data`) позволяет менять имя проекта.
   В шаблоне том назван по проекту — переименуйте его под роль до первого `up`.
8. Зависимости — по разбору импортов; `core` — колёсом.

## Если у проекта есть службы

Добавить наблюдение (сторож в `infra/health/`, юнит-пара в `infra/systemd/`, строка в списке включения
`install.sh`, имя в списке `reboot-roundtrip.sh`) — см. раздел «Наблюдение» в `infra/CONTRACT.md`.
